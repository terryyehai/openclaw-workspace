## 二、本次發現的技術問題與解決方案

### 問題一：截圖累積導致 20MB 上下文溢出

**現象**：測試進行至模塊六 INFO 項目時，出現 `Request too large (max 20MB)` 錯誤，測試中斷。

**根本原因**：
- 每張 PNG 截圖約 300–600KB（base64 編碼後更大）
- 一次完整測試產生 30+ 張截圖
- 所有截圖累積在主對話上下文，超過平台 20MB 限制

**解決方案（已實施）**：
- 採用 **Task Subagent 架構**：主對話使用 `Task` 工具啟動子代理
- 子代理負責所有瀏覽器操作與截圖，截圖資料留在子代理上下文
- 主對話只接收純文字 PASS/FAIL 結果，大幅降低主對話記憶體佔用
- 結果：模塊六透過 subagent 完成，主對話 0 張截圖，問題完全解決

**長期建議**：
- 每次 AutoTest 執行均使用 subagent 模式（已寫入 CLAUDE.md）
- 單一 subagent 截圖上限設為 50 張；若需測試更多模塊，分批啟動多個 subagent

### 問題三：座標系統文件不一致

**現象**：`h5-game-qa SKILL.md` 使用 viewport CSS 座標換算公式（`x_viewport = iframe.left + (x_ref / 430) * iframe.width`），實際執行後發現截圖像素座標可以直接使用。

**根本原因**：
- h5-game-qa SKILL.md 基於舊版測試環境設計，假設截圖與 viewport 有縮放差異
- 實際測試發現：截圖尺寸 1568×702px，點擊座標與截圖像素座標完全一致，無需換算

**解決方案（已實施）**：
- `skill.md` 中明確記錄「截圖像素座標 = 點擊座標，無需換算 viewport CSS 座標」
- 所有已驗證座標收錄於 skill.md 座標表

**長期建議**：
- 每次在新裝置/瀏覽器視窗尺寸下執行測試前，先以 1 個已知元素（如 SPIN 按鈕）驗證座標是否正確
